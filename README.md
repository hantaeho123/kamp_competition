# 제조 생산데이터 기반 전력사용량 예측 및 최대피크 위험조건 분석

제6회 K-인공지능 제조데이터 분석 경진대회(2026), 일반국민·대학(원)생 부문 **과제 ⑤ 자원 최적화 AI 데이터셋**

이 문서는 이 저장소에서 한 **모든 작업**을 처음 보는 사람도 따라올 수 있게 순서대로 기록한 것입니다.
무엇을 왜 했는지, 무엇이 실패했고 어떻게 고쳤는지, 결과 파일 하나하나가 무엇인지까지 적었습니다.

## 0. 한눈에 보기

**한 줄 요약.** 생산계획(ERP)·달력·기상만으로 **하루 전에 다음 날 96개 15분 최대수요전력**을 예측하고,
피크 전용 예측과 **전력량을 보존하는 부하 이동 시뮬레이션**으로 생산일정·설비가동 시점 조정에 따른
피크 저감량과 전기요금 절감액을 계산했습니다.

| 핵심 결과 | 값 |
|---|---|
| 시험(2021-09-01~14) 15분 예측 MAE / RMSE / CV(RMSE) | 6.36 kW / 8.74 kW / 8.5% |
| 롤링 백테스트(7~8월 8주) MAE | 7.73 kW (기준 Naive 19.88 kW, 61% 감소) |

| 80% 예측구간 실제 포함률(컨포멀 보정, 시험) | 83.0% (보정 전 73.7%) |
| 피크위험(180kW 이상) 경보 F1(시험) | 0.57 (규칙 베이스라인 0.39) |
| 예측 연동 생산일정 조정 시 시험 2주 최대수요전력 | 204 kW → 189 kW (−15 kW, −7.4%) |

**가장 중요한 발견 세 가지**
1. **데이터의 62%가 복사본입니다.** 257일 중 160일이 다른 날과 하루 96개 전력값이 완전히 같습니다(1~6월 집중).
   그래서 가이드북처럼 무작위로 나눠 검증하면 시험 표본의 58%가 학습셋에 복사본을 갖고 있어 성능이 부풀려지고,
   과거 전력값(지연값)을 넣으면 오히려 성능이 떨어집니다. → 생산계획 기반 모델 채택.
2. **피크는 재가동일 오전 기동 직후(8:15~9:00)와 27.7℃ 이상 고온일 오전에 집중**됩니다.
3. **기동 순간만 분산해서는 일 최대가 거의 안 줄어듭니다.** 8~16시 고부하 구간 자체를 낮춰야 하며,
   "하루 전 일최대 예측 ≥ 185kW인 날 주간 15kW 블록을 저녁으로 재배치" 규칙으로 15kW를 낮췄습니다.

## 4. 작업 과정 전체 기록 (시간 순서)

### 4.1 자료 파악

1. **대회 공지 확인.** 공지 페이지를 읽어 과제 ⑤의 요구사항과 제출물을 정리했습니다.
   주최 측이 **별도의 테스트 데이터나 예측 대상 구간을 주지 않는다**는 점을 확인했습니다 → 시험 구간을 우리가 정의해야 함.
2. **가이드북 읽기.** PDF 텍스트 추출이 폰트 인코딩 문제로 깨져서(`pypdf` 결과가 기호 덩어리),
   84쪽을 이미지로 렌더링(`pymupdf`)해 4쪽씩 묶어 직접 읽었습니다. 확인한 핵심 사실:
   - `15분/30분/45분/60분` = 해당 시간의 15분 구간별 **최대수요전력**(공장 변압기 센서). `평균` = 4개 값 평균
   - `생산량` = **"해당 시점에 생산해야 할 생산량"** = ERP 생산계획 → 사전에 알 수 있는 값으로 써도 됨
   - `공장인원` = 해당 시점에 공장이 보유한 생산력(환산값), `인건비` = 주간/야간 인건비 비율
   - 기상 4개 변수는 기상청 자료, 전기요금은 한전 자료를 붙인 것
   - 가이드북 실습의 평가 구간 = **2021-09-01 ~ 09-14 (336시간)** → 우리 시험 구간으로 채택(직접 비교 가능)
   - 가이드북 모델: ① SimpleRNN(직전 168시간 입력, 1시간 앞), ② RandomForest(max_depth=20, **무작위 70:30 분할**, 검증 MSE 183),
     ③ OR-Tools로 인건비+전기료 최소화 예시
   - 한전은 15분 단위 최대수요전력으로 기본요금을 산정한다는 배경 설명
3. **팀원 노트(`과제5_분석.docx`) 읽기.** `python-docx`로 본문·표를 추출했습니다. 팀원이 찾은 이상치
   (160일 복사, 07-13·07-15 시간 손상, 08-28~29 전력 0, 강수량 누적값, 02-19 생산 많은데 전력 대기수준)는
   제가 따로 검증한 결과와 **모두 일치**했습니다. 02-19는 06-19와 같은 복사 그룹에 속한 날이라 생긴 불일치입니다.

### 4.2 데이터 진단과 발견 → 처리 (`src/data.py`, `src/eda.py`)

데이터: 1개 공장(선박엔진용 볼트·너트), 2021-01-01 ~ 09-14, 257일 × 24시간 = 6,168행 × 18열.
한 행에 15분 값 4개가 있으므로 **실제 예측 단위는 24,672개 15분 슬롯**으로 다시 펼쳤습니다(long 포맷).

| # | 발견 | 어떻게 찾았나 | 처리 |
|---|---|---|---|
| 1 | **증강 복사일 160일(45개 그룹)** | 하루 96개 전력값을 해시해 같은 값을 가진 날끼리 묶음. 2·3·6월이 1월의 같은 날짜(d)를 요일이 달라도 그대로 복사(예: 01-29 금, 03-29 월, 06-29 화 동일). 4~5월도 내부 복사. 7~9월은 거의 원본 | 플래그(`aug_group`, `aug_size`) 부여. 검증은 7월 이후 원본 구간에서만, 조건별 집계는 1/n 가중, 전력 지연값 배제 근거 |
| 2 | **07-13, 07-15 시간 손상 + 행 정렬 오류(48행)** | `시간`에 0~23 대신 70~188. 처음엔 행 순서로 시간을 복원했으나, 복원된 프로파일이 정상 가동일 모양(8시 기동, 12시 점심 저하)과 전혀 달랐음 → 손상된 값 기준으로 **행이 오름차순 정렬**돼 있음을 확인. 인접일 기온·습도·풍속과 헝가리안 매칭으로 시각 복원도 시도했으나 역시 비정상 프로파일 | 두 날의 **전력값은 결측 처리(학습·평가 제외)**. 생산계획은 0으로 들어 있어 직전 4주 같은 요일·시간 중앙값으로 대체(`prod_imputed`) |
| 3 | 08-28 18시 ~ 08-29 10시 전력 0(17행) | 4개 15분 값이 모두 0, 공장인원도 같은 행에서 결측 | 계측 누락으로 결측 처리 |
| 4 | **15분 단발 0값 6개 슬롯** | 시험 예측 그래프에서 09-08 12시에 실측이 0으로 떨어지는 것을 보고 전체 탐색. 08-28 17:30~45, 08-29 11:00~15, 09-08 12:00~15. 대기전력(약 21kW)보다 낮아 물리적으로 불가능 | 결측 처리(`kw_dropout`) |
| 5 | 강수량이 일 누적값 | 1시에 0으로 초기화, 0시 행에 전일 합계 | 시간 강수량으로 차분 변환 |
| 6 | 산발 결측 | 풍속 3, 강수량 1, 공장인원 17(= #3 구간) | 선형보간, 비가동 인원은 0 |
| 7 | (날짜, 시간) 중복 키 5건 | 손상된 시간 값끼리 우연히 같음 | 시간 재구성으로 해소 |
| 8 | 파생·중복 컬럼 | `평균`=4값 평균(전 행 오차 ≤0.5), `전기요금(계절)`=월의 함수(109.8/167.2/191.6), `인건비`=시각의 함수(9~17시 1.0, 그 외 1.5), `day/d/m`=날짜의 함수(요일 100% 일치) | 모델 입력에서 제외 |

데이터 구조에서 확인한 운영 패턴:
- 가동일: 8시 기동 → 약 170kW, 12시 점심 정지 → 약 95kW, 13시 재가동, 17시 이후 감소
- 화~금 새벽 약 100kW 연속부하(야간 설비), 일요일 정지 후 월요일 새벽은 약 40kW, 비가동 대기전력 약 21kW
- 1월에는 화·수요일이 휴무라 목요일이 "재가동일" 역할
- 2021-07-31 ~ 08-08 하계휴가(대기전력만)

### 4.3 예측 과제 정의와 누수 방지 원칙 (`src/features.py`)

- **예측 시점(하루 전, day-ahead):** D-1일 24:00에 D일 96개 15분 값을 한 번에 예측.
  다음 날 생산일정을 바꿀 수 있는 마지막 시점이기 때문입니다.
- **비교용 1시간 전(hour-ahead):** 매 시각 1시간(4슬롯) 뒤를 예측. 직전 전력값 사용 가능.
- **사용 가능한 정보 원칙**
  - 생산량·공장인원: 가이드북 정의상 생산계획 → 미래 값 사용 가능
  - 기상: 실측을 "완벽한 예보"의 대리변수로 사용(한계로 명시, 기상 제외 모델로 민감도 확인)
  - 전력 지연값: 예측 시점 이전 값만(하루 전 ≥ 96슬롯, 1시간 전 ≥ 4슬롯)
- **피처 42개(최종 모델)**
  - 생산계획 24개: 당시간 계획량·공장인원, 전후 1~2시간 계획, 생산 시간 여부, 첫/마지막 생산 시각과 그로부터의 경과/잔여 시간,
    생산 시작 시간, 일 생산계획 중 비중, 점심, 일 계획량·생산시간 수·인원 합, 생산일/정상가동일, 전일·익일 계획,
    직전 정상가동일 경과일, **재가동일**
  - 달력 10개: 시각, 15분 구간, 슬롯(+sin/cos), 요일, 주말, 공휴일, 월, 연중 일차
  - 기상 8개: 기온, 습도, 풍속, 시간 강수량, 냉방도(기온−24), 난방도(18−기온), 일 최고·평균 기온
- **정상 가동일·재가동일 정의:** 처음에는 "생산량 > 0인 날"을 가동일로 했더니 토요일 소량 생산 때문에

### 4.10 피크 저감 시뮬레이션과 운영 규칙 (`src/peak_shaving.py`)

**(1) 선형계획 시뮬레이션(7~9월 실측 프로파일, 하루 단위)**
- 기저부하 = 당일 0~6시 중앙값(이동 불가), 이동 가능 부하 = α × (부하 − 기저)
- 슬롯 t의 부하를 허용된 슬롯 s로 옮기는 양 x(t→s)를 변수로, **하루 최대값을 최소화**(전력량 보존, scipy HiGHS)
- 시나리오별 허용 이동 범위
  - S1 순차 기동: 기동구간(첫 생산~+2h) 부하를 1~2시간 앞으로(경부하 시간대 선기동)
  - S2 점심 교대: 13시대 재가동 부하를 12시대로
  - S3 주간→저녁 생산 이전: 08~17시 부하를 17~22시로
  - S4 ±2시간 자유 이동(06~22시): 가동 시점 조정의 상한

| 시나리오(α=20%) | 가동일 일피크 평균 감소 | 재가동일 감소 | 최대수요전력(7~9월) | 연간 기본요금 절감 |
|---|---|---|---|---|
| S1 순차 기동 | 0.8kW(0.4%) | 3.7kW | 222 → 222kW | 0원 |
| S2 점심 교대 | 0.2kW(0.1%) | 0kW | 222 → 222kW | 0원 |
| S3 주간→저녁 | 19.7kW(9.8%) | 27.4kW | 222 → 194.8kW | 약 244만 원 |
| S4 ±2h 최적(상한) | 22.4kW(11.3%) | 35.5kW | 222 → 194.8kW | 약 244만 원 |

- S1·S2는 α를 키워도 효과가 늘지 않습니다. 기동 순간을 깎아도 10~11시 고원 구간이 새 최대가 되기 때문입니다.
- S3는 α 10·20·30%에서 일피크 5.4·9.8·12.1% 감소. S4 α=30%는 16.3% 감소, 최대수요전력 183.5kW(연 약 345만 원).

**(2) 예측 기반 운영 규칙(실측을 모르는 상태에서 하루 전에 세울 수 있는 계획)**
- 위 LP는 실측 프로파일을 안다고 가정한 상한이므로, 현실적인 규칙을 따로 만들어 시험 구간에서 검증했습니다.
- **1차 시도(실패):** 경보일에 주간 기저초과 부하 20%를 17~22시에 균등 배분 → 09-13은 196kW가 **215.7kW로 악화**.
  저녁 5시간에 너무 많은 전력량을 몰아넣어 저녁이 새 피크가 됨.
- **2차(채택):** 경보일에 주간(08~17시) 설비 블록 Δ kW를 줄이고, 옮긴 전력량을 **예측 프로파일상 여유가 큰 17~24시 슬롯에 여유에 비례해** 배분.
  줄이는 양도 예측 프로파일로 계획하고, 그 계획을 실측에 적용해 평가합니다.

| 경보 기준(일최대 예측) | 조치일 | 시험 2주 최대수요전력 | 전력량요금 변화(2주) |
|---|---|---|---|
| 조치 없음 | 0 | 204.0kW | 0원 |
| ≥ 195kW | 1 | 204.0kW | −1,369원 |
| ≥ 190kW | 6 | 204.0kW | −8,303원 |
| **≥ 185kW(제안)** | **10** | **189.0kW** | **−13,920원** |

(Δ=15kW 기준. Δ=10kW면 194kW, Δ=20kW면 188.1kW.)
- 목표 190kW를 그대로 경보 기준으로 쓰면 09-10(실측 204, 예측 188)을 놓칩니다. **목표 − 일피크 예측오차(약 5kW) = 185kW**를 쓰는 것이 핵심.
- 22~24시 경부하 시간대로 일부가 옮겨져 전력량요금도 줄었습니다.

**(3) 현장 운영 절차(제안)**
1. 전일 오후 생산계획 확정 직후 모델 실행 → 다음 날 96슬롯 예측, 80% 구간, 일 최대 예측
2. 일 최대 예측 ≥ 185kW → 피크 경보일 지정, 조치 대상 라인 결정
3. 조치: 주간 설비 블록 15kW를 저녁 여유 시간대로 재배치. 재가동일엔 예열성 설비(열처리로·컴프레서 등)를 6~8시 경부하에 선기동.
   27.7℃ 이상 고온 예보일엔 오전 생산 일부를 오후·저녁으로 미룸
4. 당일: 15분 예측 ≥ 175kW 슬롯은 추가 설비 기동을 미루도록 작업자에게 알림
5. 사후: 예측과 실측 비교, 특수일·점심 정지 여부를 ERP에 기록해 매주 재학습

### 4.12 개발 중 겪은 기술 문제와 해결

| 문제 | 원인 | 해결 |
|---|---|---|
| 가이드북 PDF 텍스트가 깨짐 | 폰트 인코딩 | 페이지를 이미지로 렌더링해 읽음 |
| pandas 정수 컬럼에 실수 대입 오류 | pandas 3.x의 엄격한 dtype | 생산량을 float로 변환 |
| LightGBM 백테스트가 33초 → 693초로 급격히 느려짐 | macOS에서 LightGBM·XGBoost·CatBoost가 각자 OpenMP 스레드를 다툼 | 모든 모델 스레드 4개 고정, `OMP_NUM_THREADS=4` |
| MLP 학습 시간 34~430초 편차 | 실행 환경(전원·발열) 영향으로 추정, 합성 데이터로는 재현 안 됨 | 실행 시간 안내를 6~17분으로 명시 |
| 07-13 일별 프로파일 조회 KeyError | 전력을 전부 결측 처리한 날이 피벗에서 빠짐 | 전력 관측이 80슬롯 이상인 날만 "직전 가동일"로 참조 |
| 오차분석 crosstab 인덱스 중복 오류 | 백테스트·시험 예측을 이어 붙일 때 | 인덱스 재설정 |
| 저감 예시 그림이 빈 화면 | 결측일(07-15)이 예시로 선택됨 | 결측 20% 이상인 날 제외, 단발 결측은 보간 |
| B2 규칙의 시험 MAE가 NaN | 09-08 누락 슬롯이 다음 날 규칙 예측을 결측으로 만듦 | 지난주 동시각 → 7일 평균 → 전일 순으로 대체, 지표 계산 시 예측 결측도 제외 |
| 매번 전체 재실행이 오래 걸림 | 백테스트 13개 구성 | `--reuse-cv` 캐시 옵션 추가 |

모든 수정 후 캐시 없이 처음부터 전체를 다시 실행해 보고서 수치와 일치함을 확인했습니다
(이때 B2 규칙의 백테스트 수치만 대체값 처리 때문에 17.04 → 17.30으로 바뀌었고 보고서에도 반영).

## 10. 용어 설명

| 용어 | 뜻 |
|---|---|
| 15분 최대수요전력 | 15분 동안의 평균 전력(kW). 한전 기본요금 산정 단위 |
| 요금적용전력 | 기본요금을 매기는 kW. 직전 12개월 중 12·1·2·7·8·9월과 당월 최대수요전력 중 최대 |
| MAE / RMSE | 평균 절대오차 / 평균 제곱근오차(큰 오차에 더 민감) |
| CV(RMSE) | RMSE ÷ 실측 평균. 규모가 다른 모델끼리 비교할 때 사용 |
| 롤링 원점 백테스트 | 과거로만 학습하고 바로 다음 기간을 예측하는 검증을 시점을 옮겨 가며 반복 |
| 데이터 누수 | 평가 데이터의 정보가 학습에 섞여 성능이 부풀려지는 현상 |
| 재가동일 | 직전 정상 가동일(일 계획 5,000개 이상)과 2일 이상 떨어진 정상 가동일(대개 월요일) |
| 분위수 회귀 P10/P90 | "실측이 이 값보다 작을 확률 10%/90%"인 값을 직접 예측 |
| CQR | 백테스트 잔차로 분위수 구간 폭을 보정해 목표 포함률을 맞추는 방법 |
| SHAP | 각 변수가 예측값을 얼마나 올리고 내렸는지 나누어 보여주는 설명 방법 |
| F1 / 정밀도 / 재현율 | 경보 성능. 정밀도 = 경보 중 진짜 피크 비율, 재현율 = 진짜 피크 중 경보한 비율 |
| FN / FP | 놓친 피크 / 헛경보 |
| 선형계획(LP) | 선형 제약 아래 목적함수(여기선 하루 최대 전력)를 최소화하는 최적화 |
