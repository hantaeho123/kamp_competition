제6회 K-인공지능 제조데이터 분석 경진대회(2026) 과제 ⑤ 자원 최적화 AI 데이터셋

분석은 **0~6단계**로 진행하며, 단계마다 "무엇을 했나 → 근거 → 결과 → 결과 파일" 순서로 적었습니다.
결과 파일은 `outputs/step0_…` ~ `outputs/step6_…` 폴더에 단계별로 들어 있습니다.

```bash

pip install -r requirements.txt
python run_all.py              # 0~6단계 전체 자동 실행(약 6~17분)
python run_all.py --reuse-cv   # (개발용) 1단계 모델 비교 캐시 재사용
```

## 4. 단계별 내용

### 0단계. 데이터 전처리 및 분할 → `outputs/step0_preprocess_split/`

데이터는 1개 공장의 2021-01-01~09-14, 257일 × 24시간 = 6,168행입니다. 한 행에 15분 값 4개가 있어 **24,672개 15분 슬롯**으로 펼쳤습니다.

**결측·이상치 처리** (`data_cleaning_actions.csv`)
| 항목 | 근거 | 처리 |
|---|---|---|
| 07-13, 07-15 시간 손상(48행) | `시간`에 70~188 값. 그 값 기준으로 행이 정렬돼 실제 시각 불명. 기상 매칭 복원도 정상 프로파일과 불일치 | 두 날 전력은 제외 |
| 08-28 18시~08-29 10시 전력 0(17행) | 4개 값 모두 0, 공장인원도 결측 | 결측 처리 |
| 15분 단발 0값 6개 | 대기전력(약 21kW)보다 낮아 물리적으로 불가능 | 결측 처리 |
| 강수량 | 1시에 초기화되는 일 누적값 | 시간 강수량으로 변환 |
| 풍속 3, 강수량 1, 공장인원 17 결측 | 산발 결측 | 보간, 비가동 인원 0 |

**중복 데이터 확인** (`eda_augmentation_calendar.png`)
- 하루 96개 전력값이 다른 날과 **완전히 같은 날이 160일(45개 그룹)** 입니다.
- 복사는 **1~6월 안에서만** 일어났습니다. 1월 → 2·3·6월(같은 날짜를 요일이 달라도 복사), 4월 → 5월.
- **7~9월은 복사가 거의 없는 원본 구간**입니다(7월 28일·30일 한 쌍만 동일).
- 1~6월의 어떤 날·어떤 시간도 7~9월과 일치하지 않습니다(가장 가까운 날도 평균 1kW 이상 차이).
  따라서 "7~9월 데이터로 1~6월을 만들었다"는 데이터로 확인되지 않으며, 확인된 사실은 "1~6월은 서로 복사해 늘렸고 7~9월은 원본"입니다.

**누수·중복 변수 제거** (`leakage_and_redundant_variables.csv`)
- `평균`(목표값의 평균), `전기요금(계절)`(월의 함수), `인건비`(시각의 함수) 제거
- 전력 지연값(전일·전주 값)도 제외: 복사일이 날짜 간 연속성을 깨뜨려 넣으면 MAE가 7.73 → 11.99kW로 나빠짐

**시간 순 Train / Valid / Test 분할** (`train_valid_test_split.csv`)
- Test: 2021-09-01~14 (1,342슬롯, 최종 1회만 평가). 가이드북 실습과 같은 구간
- Valid: 7/5~9/5 사이 주 단위 8개 fold 롤링 방식. 각 fold는 **그 이전 데이터로만** 학습
- 평가 구간을 원본 구간에 둔 근거(`split_leakage_check.csv`): 가이드북의 무작위 70:30 분할에서는 시험 표본의 **58.3%가 학습셋에 복사본**이 있어 MSE가 106.8로 시간 순 분할(113.1)보다 낙관적

### 1단계. 전력 예측 → `outputs/step1_forecast/`, `outputs/predictions/`

- **과제 정의:** D-1일 24시에 D일 96개 15분 최대수요전력을 예측(다음 날 생산일정을 바꿀 수 있는 마지막 시점)
- **입력 42개:** 생산계획 24개(가이드북상 생산량 = "생산해야 할 생산량"이므로 사전에 아는 값), 달력 10개, 기상 8개

| 모델(백테스트 8주) | MAE | RMSE | 가동일 일최대 MAE | 피크 F1 |
|---|---|---|---|---|
| 베이스라인1 Naive(지난주 같은 시각) | 19.88 | 40.61 | 33.71 | 0.50 |
| 베이스라인2 규칙(직전 가동일 프로파일) | 17.30 | 30.37 | 8.55 | 0.63 |
| Ridge / RandomForest / MLP | 20.92 / 9.16 / 12.61 | 26.53 / 15.50 / 21.30 | | |
| XGBoost / CatBoost | 7.72 / 8.10 | 11.29 / 11.43 | | |
| **LightGBM(최종)** | **7.73** | **11.21** | 13.18 | 0.62 |

- **선정 근거:** MAE 공동 1위, RMSE 최저, 시험 MAE 최저(6.36), 분위수 예측을 같은 학습기로 만들 수 있음, 학습 12초
- **시험 결과**(`test_metrics.csv`): MAE 6.36kW, RMSE 8.74kW, CV(RMSE) 8.5%
- **피크 보완**(`daily_peak_comparison.csv`): 15분 예측은 일 최대를 13kW 낮게 봄 → 일 단위 모델 + 직전 가동일 규칙을 섞은 일 최대 예측으로 시험 MAE 5.29kW
- **불확실성:** P10~P90 구간을 백테스트 잔차로 2.23kW 넓혀 시험 포함률 83.0%(목표 80%)
- **경보:** 백테스트에서 F1이 최대인 기준(예측 ≥ 175kW) 선택 → 시험 F1 0.57

|---|---|---|---|
| 전체 | 6,454 | 7.44 | +0.15 |
| 피크 아닌 시간 | 5,776 | 6.98 | +1.34 |

| 유형2 피크 구간 | 277 | 10.84 | −9.39 |

→ 피크 시간에는 오차가 1.5배이고 거의 전부 과소예측입니다. 그래서 피크는 1단계의 일 최대 전용 예측과 경보 기준 하향(180 → 175kW)으로 보완했습니다.

**시간대·생산조건·가동상태별** (`error_by_phase_oos.csv` 등)
| 조건 | MAE | 해석 |
|---|---|---|
| 비가동일 / 새벽 | 3.74 / 6.33 | 부하가 낮고 안정적 |

### 3단계. 실제 피크 추출 → `outputs/step3_peak_extraction/`

- **정의:** 15분 최대수요전력이 **180kW 이상인 연속 구간**. 15분 한 칸만 내려갔다 다시 넘으면 한 구간으로 합침
- **기준의 근거:** 180kW는 전체 슬롯의 95번째 백분위수. 기준을 바꿔 본 결과는 `threshold_sensitivity.csv`
  (170kW면 599개로 가동 시간 대부분이 포함되고, 190kW면 200개로 줄어 유형 비교가 어려움)
- **결과:** 426개 구간. 복사일을 한 번만 세면 **267개(78일)**. 7~9월 정상 가동일 47일 중 46일에 피크 발생
- 구간마다 시작 시각, 지속시간, 최대값, 직전·직후 1시간 평균, 상승폭을 계산

### 4단계. 피크 두 유형 구분 → `outputs/step4_peak_types/`

- **방법:** 구간별 (상승폭, 지속시간, 직전 1시간 부하)을 표준화해 K-means로 묶음. 복사일 중복을 막으려고 고유한 날의 267개 구간으로 학습
- **왜 2개인가:** 묶음 수 2~6 중 실루엣 점수가 2개일 때 0.51로 최고(3개 0.42) — `cluster_count_selection.csv`

| 특성(중앙값) | 유형1: 시작·재개 직후 크게 오르는 피크 | 유형2: 가동 중 잠깐 더 오르는 피크 |
|---|---|---|
| 구간 수 | 86 | 181 |
| 직전 1시간 평균 부하 | 128kW | 168kW |
| 상승폭 | 64.5kW | 19.3kW |
| 지속시간 | 90분 | 30분 |
| 최대값 | 194.5kW | 185.0kW |
| 직후 1시간 평균 | 167.5kW | 162.3kW |

여섯 특성 모두 두 유형 간 차이가 통계적으로 유의합니다(순위합 검정 p < 0.001, `type_difference_tests.csv`).
전후 패턴은 `peak_types.png` 가운데 그림: 유형1은 100kW 부근에서 급등해 높은 수준이 이어지고, 유형2는 160kW대에서 잠깐 솟았다가 30분 안에 내려옵니다.

- 보조 분석(15분 슬롯 단위, `peak_tree_rules.csv`): 기온 27.7℃ 초과 & 11:30 이전이면 피크 확률 70.7%

### 6단계. 저감방안 → `outputs/step6_mitigation/`

7~9월 실측 프로파일에 **전력량을 보존하는 부하 이동 선형계획**을 적용했습니다.
기저부하(0~6시 중앙값)를 넘는 부하 중 α 비율만 가동 시점을 옮길 수 있다고 가정합니다.

| 조치(α = 20%) | 대상 | 유형1 구간 최대 | 유형2 구간 최대 | 피크 발생일 일최대 감소 |
|---|---|---|---|---|
| A. 설비 가동시점 분산: 시작·재개 후 2시간 부하를 직전 2시간으로 앞당김 | 유형1 | 197.4 → 194.6 | 변화 없음 | 3.3kW(1.6%), 재가동일 5.7kW |
| B. 생산일정 이동: 피크 구간 생산을 17~22시로 | 유형2 | 변화 없음 | 187.6 → 184.4 | 4.5kW(2.3%) |
| **A + B 동시** | 둘 다 | 197.4 → 190.7 | 187.6 → 181.3 | **11.5kW(5.8%)**, 재가동일 14.4kW |
| 상한: ±2시간 자유 이동 | 전체 | → 180.1 | → 175.1 | 22.5kW(11.3%) |

- **한 유형만 줄이면 다른 유형이 그날의 최대가 됩니다.** 그래서 따로는 3~5kW, 함께는 11.5kW입니다
- A + B(α=20%)는 유형2의 180kW 이상 시간을 42% 줄이고, 7~9월 최대수요전력을 222 → 212kW로 낮춤(기본요금 연 약 90만 원, 1kW당 연 89,640원)
- **예측 연동 운영 검증**(`forecast_driven_policy_test.csv`): 실측을 모르는 상태에서 "하루 전 일최대 예측 ≥ 185kW인 날, 주간 15kW 블록을 저녁 여유 시간대로 재배치" →
  시험 2주 최대수요전력 **204 → 189kW**, 전력량요금 −13,920원. 기준을 190kW로 두면 09-10(실측 204, 예측 188)을 놓쳐 효과 0 → 목표에서 예측오차 5kW를 뺀 값을 기준으로 써야 함
- 요금 기준: 한전 산업용(갑)Ⅱ 고압A 선택Ⅱ 기본요금 7,470원/kW·월(최대 222kW로 계약전력 300kW 미만 가정, `src/config.py`에서 변경 가능)

| # | 사실 | 근거 |
